# 分散関数の欠如

!!! info "前提知識"
    [基底関数系](../methods/basis-sets.md)

アニオンの余分な電子は弱く保持されていて、原子核から遠くまで広がっている。中性分子向けにつくられた[基底関数系](../methods/basis-sets.md)にはそこまで届く関数がないので、計算は電子を無理に押し込め、それがエネルギーを押し上げる。アニオンは高すぎ、電子親和力は小さすぎ、しばしば負になる。対策は**分散関数** (diffuse functions)、つまり指数の小さい広がった基底関数である。

!!! note "用語"
    「分散関数」(diffuse function) と「分散力」(dispersion) は日本語では同じ「分散」を使うが、まったく別の概念である。前者は基底関数の種類、後者は分子間の引力である ([分散力の欠如](dispersion.md))。

## 考え方

指数 $\alpha$ のガウス関数 $e^{-\alpha r^2}$ の広がりはおよそ $1/\sqrt{\alpha}$ ボーアである。標準的な基底関数系は中性原子に合わせられており、水素での最小の指数は 0.1 程度、広がりは約 3 ボーアである。ところが弱く束縛された電子は原子単位で $\kappa = \sqrt{2\,\text{EA}}$ として $e^{-\kappa r}$ のように減衰する。EA = 0.0277 ハートリーの [H⁻](app:s/1/-1/1) では $\kappa = 0.24$ であり、電子は 4 ボーアを超えて広がる。基底が記述できる範囲をはるかに超えている。

この手法は基底の範囲で[変分的](../foundations/schrodinger-equation.md#the-variational-principle) なので、窮屈な電子は単にエネルギーが高くなる。より小さな指数の関数 (基底名の **aug-** や **-D**) を加えると、電子に居場所ができる。

## 例: 分散関数のある [H⁻](app:s/1/-1/1) とない [H⁻](app:s/1/-1/1)

[`h_minus_diffuse.py`](#the-code) は、s 型ガウス関数で H と [H⁻](app:s/1/-1/1) を厳密に (完全 CI で) 計算する。出発点は、[基底関数系](../methods/basis-sets.md#example-the-hydrogen-atom)のページで中性の水素原子に対して最適化した 4 関数の基底である。そこに、指数が次々に小さくなる分散関数を加えていく:

```text
basis                       E(H)     E(H-)   EA (eV)
fitted to the H atom    -0.49874  -0.46001    -1.054
+ 1 diffuse             -0.49879  -0.50856     0.266
+ 2 diffuse             -0.49881  -0.51325     0.393
+ 3 diffuse             -0.49881  -0.51337     0.396
```

- 中性原子は関数が増えてもほとんど気づかない (−0.49874 → −0.49881)。その電子はそこまで遠くへは行かないからである。
- **分散関数のない [H⁻](app:s/1/-1/1) は 1.05 eV だけ非束縛になる。**定性的な誤りである。分散関数 1 つ (α = 0.04) で束縛には十分で、2 つで結果は収束する。
- 収束した 0.39 eV は s 関数だけの極限である。実際の 0.754 eV には p 関数と d 関数も必要で、それらが原子核のまわりで 2 つの電子が互いを避ける様子 (角度相関) を記述する。

```python
--8<-- "h_minus_diffuse.py:fci"
```

## このプロジェクトでは

r²SCAN-3c (L0) には分散関数のない独自の基底がついている。その H の電子親和力は−1.57 eV で、おもちゃのモデルとほぼ同じ失敗である (自己相互作用がそれに上乗せされている)。L1、L1M、L2 の基底にはどれも分散関数があり、EA は正である (0.20、0.48、0.73 eV)。

## 分散関数の代償

- **線形従属。**隣り合う原子上の分散関数はほとんど完全に重なり合うので、重なり行列が特異に近くなり、SCF の収束が難しくなる。プログラムはほぼ従属な組み合わせを取り除く (おもちゃのコードもそうしている: `keep = s > 1e-8`)。
- **コスト。**関数が増える。aug-cc-pVTZ は H 1 個あたり 23 関数で、cc-pVTZ の 14 関数より多い。
- **見かけの束縛。**非常に広がった関数は、本来束縛されるべきでない電子を保持してしまうことがある ([非束縛アニオン](unbound-anions.md))。

## [h_clusters](https://github.com/skachano/h_clusters) での登場箇所 { #where-this-appears-in-h_clusters }

- 計画は分散関数を必須とし、アニオンだけでなく**すべての**化学種に使って、どの電荷状態も同じように扱われるようにしている (`doc/Plan.md` §2): def2-TZVPP**D** (L1)、**aug**-cc-pVTZ (L1M、L2)。
- L0 に分散関数がないことが許されるのは、L0 が選別用のレベルだからにすぎない。アニオンのエネルギーが L0 からとられることはない。
